# DSH 遠端版（VPS 常駐）

**入口（永遠有效，兩台都用這個）**：https://dsh-149-88-70-170.sslip.io/login/

## 怎麼用
1. 雙擊 `DSH 網頁.url`（就是上面那個 /login/ 網址）。
2. `/login/` 每次都會自動讀取「本次啟動的最新 token」，跳轉到 `/?token=…`，DSH 接著發一個簽章 cookie（30 天）給該瀏覽器。
3. 之後同一台電腦、同一個瀏覽器，開 `https://dsh-149-88-70-170.sslip.io/` 也能直接進去（cookie 認證）。
4. 公司和家裡各開一次 `/login/` 即可，兩邊看到的是**同一份會話與記憶**。

> 為什麼第一次會失敗：`/` 這條路徑沒有 token、也沒有 cookie 就是 401，頁面會寫「reopen the URL printed by dsh web」。所以入口一律用 `/login/`，不要用裸網址。

## 工作區（重要）
- **預設工作目錄 = `/srv/DSH_Workspace`**（systemd `WorkingDirectory`，2026-10-20 改定）。
- 開新會話就在這裡落腳；也可以在側欄「添加工作區」另外註冊資料夾（VPS 上走應用內瀏覽對話框，不是 Windows 選檔視窗）。
- 工作區與「不能丟」的東西分開：`/root/.dsh` 放憑證、記憶庫、會話紀錄、插件；`/srv/DSH_Workspace` 放您的工作檔案。
- 磁碟只有一個 `/` 分區（68G，剩 40G），所以放哪都同一塊碟。

## 日常操作（在 VPS 上，root）
```bash
systemctl status dsh-web            # 狀態
systemctl restart dsh-web           # 重啟（會自動重寫 /login/ 頁，入口不變）
tail -1 /var/log/dsh-web.log        # 看本次 token
npm i -g @deepseek-ai/dsh@latest    # 升級 DSH
systemctl restart dsh-web           # 升級後重啟
dsh plugin --profile web add <套件>  # 加插件
dsh plugin --profile web remove <套件>
```

## 重要限制（別忘）
- VPS 的工作區是**另一台機器**：看不到您本機的 `page.html`、ComfyUI 工作流；要用 SSH 連 824 或在那邊 clone 檔案。
- 反向代理設定在 `/root/caddy-8090/Caddyfile`（原始版備份 `Caddyfile.bak_before_dsh`），跟 8090 那支共用同一個 caddy 容器，**不要**再開第二個 caddy（443 衝突）。
- VPS 沒有防火牆（ufw 未啟用），DSH 只綁 `127.0.0.1:3080`，對外一律經 caddy + HTTPS。
- `dsh plugin` 需要 pnpm：`export COREPACK_NPM_REGISTRY=https://registry.npmmirror.com; corepack enable; corepack prepare pnpm@10.15.0 --activate`（已做過，重開機仍在）。
